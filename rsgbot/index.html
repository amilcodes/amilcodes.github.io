00 / THE QUESTION

How much of the game should
live in the harness?

The goal is to complete Minecraft from an unseen random seed, without a route fixed in advance. Gathering tools leads to iron, a portal, the Nether, blaze rods and pearls, a stronghold, and finally the dragon. Each stage changes the resources, hazards, and decisions that follow.

The early system encoded that sequence in skills and guards. Live attempts exposed a different bottleneck: the harness sometimes cancelled useful actions, misread state, or hid the evidence the model needed. The current direction gives the model richer observations and simpler actions, then measures what actually happened.

Current scope. The evidence below comes from instrumented practice runs and offline experiments through October 14, 2026. Prepared-kit and prepared-frame scenarios are labeled. A full random-seed completion has not been demonstrated.

The game interface

A Fabric practice client exports frames, accepts leased input, and freezes game ticks while the model thinks. The body layer manages the frame grabber, keyboard and mouse events, input heartbeat, maximum holds, and operator pause.

This separates game time from model latency. It also creates engineering obligations: a stale frame or a released attack key can look like a reasoning failure when the decision itself was sound.

The decision interface

The model receives the current frame, stitched views, visible vitals, inventory estimates, a progression ladder, an objective tree, a spatial map, action effects, and advisory messages. It chooses basic operations such as look, move, sneak, mine, use, and click a slot.

Sessions are divided into chapters of at most 30 steps or 150k tokens, with a model-written summary carrying the attempt forward. This preserves continuity without resending an unlimited history.

⊞

The evaluator has a separate view.

Privileged game state is used to set up practice scenarios and score outcomes. It is kept outside the agent’s observation path. Practice instrumentation and tick freezing mean these results do not count as an uninstrumented ruleset run.

05 / APPROACH & EXPERIMENTS

From scripted skills to an informed model.

02–06 OCT

Build the environment and a skill hierarchy

A perception stack, world model, motor layer, progression knowledge, evaluation harness, and practice mod. The first live wood-to-stone runs exposed OCR, camera, inventory, and action-timing bugs.

Foundation
06–07 OCT

Compare program control with per-step decisions

Commander generated short programs; Direct v1 made stateless decisions. Across 20 stage attempts, neither produced a stage pass. The best stone pickaxe took 915 seconds of game time.

Superseded
07–09 OCT

Keep the conversation and make guards advisory

Direct v2 retains a session across the attempt. NEXT, TREE, and MAP make progress and remembered terrain explicit. Fixes to input holds, OCR masking, and action cancellation accompanied the first 3/3 stone-tool results.

Kept
10–14 OCT

Teach the route; simplify the action surface

A roughly 4,300-word route guide replaces more strategy code. The lean arm removes coded gather, navigation, and portal skills. A model using basic actions completed and lit a frame where scripted portal control had repeatedly failed.

Current direction

Where learned controllers fit

VPT, STEVE-1 with MineCLIP, and ROCKET-3 with SAM 2 were evaluated as alternative low-level controllers offline. STEVE-1’s tree prompt aimed at logs 3–4× faster than random turning but did not find them more often. In an aiming probe, ROCKET-3 reached 16 of 39 targets and held attack on four. These controllers were never used in the reported live passes.

06 / FAILURE NOTES

The hard part is
closing the loop.

01

Action effects need fresh evidence.

Bucket use, movement, and held attacks exposed stale-frame and input-heartbeat failures. The model needs to see what changed before planning the next operation.

02

Safety code can interrupt progress.

Some guards treated working actions as stalls or inferred danger from unreliable pixels. The experimental pure arm moves alerts into the next context packet as advice, leaving strategic decisions to the model.

03

A simulated skill can fail on the next layout.

Portal casting depends on stance, reach, water flow, terrain, and where a bucket ray lands. Scripted simulation improvements did not transfer reliably to unfamiliar live sites.

04

Game time hides the cost of thinking.

Reported live decision latency was roughly 5–8 seconds per step for Opus and 19 seconds for Sol, with 200–800 steps per attempt. Tick freezing helps study decisions, but wall time remains a practical constraint.

07 / NEXT QUESTIONS

Get through the next arrival.
Then earn the next milestone.

Reliability. Make lava search, water handling, and portal arrival robust across unfamiliar layouts.

Evaluation. Expand the sample of independent seeds and preserve explicit prepared-state versus fresh-spawn accounting.

Long horizon. Carry grounded memory through Nether travel, resource collection, stronghold search, and the End.

These are research directions, not completed capabilities. This page summarizes the project’s recorded state through October 14, 2026.
