RSGbot

Java 1.16.1

A pixel-based Minecraft agent

RSGbot uses a vision-language model to play Minecraft through rendered frames and keyboard/mouse inputs. We built a Python agent, a Java practice mod, and an evaluation harness to study long-horizon control: gathering resources, crafting tools, finding lava, and building a Nether portal in an unfamiliar world.

The current agent keeps a persistent conversation, reconciles visual observations with remembered state, and chooses basic actions. It reached stone tools in 3/3 practice runs and built and entered its own portal from a prepared-kit start. Nether survival and a full random-seed completion remain unresolved.

Architecture

Rendered observations → model decisions → game input

The agent and evaluator use separate interfaces. The agent receives rendered information; privileged game state is reserved for scenario setup and scoring. The practice client freezes game ticks while the model thinks, allowing game time and wall time to be measured separately.

Perception

Frame capture, F3 OCR, HUD and hotbar icons, inventory screens, subtitles, hazard pixels, and stitched directional scans.

Visual observations →

State + memory

A fused world snapshot, inventory ledger, landmarks, spatial map, failure index, and summaries carried between chapters.

Context packet →

Decision

One persistent model session per attempt. Progression knowledge, objective prerequisites, route guidance, and advisory alarms.

1–4 actions →

Motor

Basic actions with exact turns and tick counts: look, move, sneak, mine, use, select a hotbar slot, or click inventory.

Input → fresh frame ↺

Practice client

A Java Fabric mod exports frames and accepts background input under a lease. The body layer maintains the input heartbeat, limits key holds, and supports operator pause. The model’s thinking time advances wall time but not game ticks.

Persistent control

Direct v2 keeps one conversation per attempt. Chapters close after at most 30 steps or 150k tokens, with a model-written summary for the next chapter. The lean arm removes coded navigation, gathering, and portal skills.

What the context packet contains
FRAME
The current rendered image and labeled scans.
NEXT / TREE
The next progression milestone and its resource prerequisites.
MAP
Remembered landmarks and spatial relationships.
SOUND
Visible sound subtitles from the game.
EFFECTS
Changes observed after the previous actions.
ADVISORIES
Hazard, stall, loop, and stuck-detector messages.

The route guide contains roughly 4,300 words of version-specific instructions, including digging, lava handling, portal casting, and Nether movement. These are written instructions to the model; they do not execute a route.

State representation

Observations, remembered facts, and objectives

Perception can be incomplete or stale. The world model combines observations into one snapshot per tick, tracks inventory changes, and distinguishes proposed changes from verified outcomes. Requesting a mining or crafting action does not establish that an item was acquired.

ObservedF3 readout, HUD, inventory, subtitles, hazards, camera geometryEstablish what is visible in the current frame; track freshness and consistency.
RememberedLandmarks, spatial map, inventory ledger, failure index, chapter summariesRetain context across camera changes, decisions, and session chapters.
PlannedProgression ladder, objective tree, recipe goals, route guidanceConnect the current state to the next resource or progression requirement.
MeasuredEvaluator-only ground truth and attempt outcomesScore progress without putting privileged state into the agent’s observations.

Recorded decisions, action effects, frames, oracle traces, and videos make each attempt inspectable. Continuation segments resume a world with the model’s carry notes rather than silently restarting it.

Experiments

Live attempts and offline comparisons are reported separately

Control architecture

The initial system used coded skills with a strategist and skill picker. Commander then generated short programs; Direct v1 made stateless per-step decisions. Across 20 early stage attempts, neither produced a stage pass. The best stone pickaxe took 915 seconds of game time.

Direct v2 added persistent conversation state. Subsequent iterations added explicit progression context, made guards advisory, corrected input holds and OCR masking, and simplified the motor interface. The first 3/3 stone-tool results followed these combined changes; the live runs do not isolate any single change’s effect.

Progression context ablation

An offline replay used 20 saved decision points where the agent wandered or repeated a failure, with 120 model calls. The NEXT block supplied the progression ladder.

Learned low-level controllers

VPT, STEVE-1 with MineCLIP, and ROCKET-3 with SAM 2 were tested offline as possible motor controllers. STEVE-1’s tree prompt aimed at logs 3–4× faster than random turning but did not find them more often. ROCKET-3 reached 16/39 targets and held attack on four in an aiming probe. None drove the reported live attempts.

Development notes

Failures that changed the implementation

Held inputs and stale frames

The input heartbeat initially released attack while mining a log. Bucket use and camera motion also exposed stale-frame problems. Fixes focused on maintaining input state and acquiring fresh evidence after an action.

Guard behavior

Some guards cancelled working actions or interpreted unreliable pixels as hazards. In the pure experimental arm, alarms enter the next observation packet as advice rather than overriding the model’s decision.

Portal construction

The scripted portal skill improved in simulation but failed on unfamiliar live layouts. Stance, reach, bucket rays, and water flow made the skill brittle. The basic-action arm completed and lit a frame using a written route guide.

Arrival conditions

Both successful portal entries linked to an old Nether portal on a basalt ledge. Subsequent setup changes unlit that portal. Surviving a fresh arrival remains unverified.

Latency

Attempts took roughly 200–800 decisions. Tick freezing separates reasoning latency from game time, but 5–19 seconds per decision still makes long runs expensive in wall time.

Next work

Improve lava search and portal arrival reliability, evaluate independent seeds, and extend grounded memory through Nether resources, stronghold search, and the End. These stages have not been demonstrated.
